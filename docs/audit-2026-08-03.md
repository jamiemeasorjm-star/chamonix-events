# Chamonix Events — Full Audit & Review

Audit date: 2026-08-03 · Target: workspace.srv1626662.hstgr.cloud/events/ (nginx:8095 → python:8090)
Scope: live-site functionality, data layer, scrapers, images, date filtering, aesthetics, new sources.

---

## Executive summary

The site is **visually excellent and functionally sound at the front-end layer** — no JS errors, date/search/category filtering all work, and the design system is genuinely high standard. **Every one of the 39 published events has an image (100% coverage).**

The problems are concentrated in the **data pipeline**, where three bugs cause real, user-visible breakage:

1. **🔴 Cinema section is completely empty** (root cause found).
2. **🔴 The daily briefing's "EVENTS THIS WEEK" never works** (wrong DB).
3. **🟠 Footer renders "NaNj"** (build script corrupts its own JS regex).
4. **🟠 Review queue is flooded (664 open items), 65% garbage** from the nightlife scraper.

Severity count: **2 critical, 3 high, 4 medium, 4 low.**

---

## Critical bugs

### 🔴 C1 — Cinema section broken end-to-end (empty forever)
- `vox_pdf.py` correctly parses the Le Vox PDF → **15 films** with showtimes + TMDB posters.
- But `get_storage().upsert_cinema()` crashes: `sqlite3.IntegrityError: UNIQUE constraint failed: cinema_events.id`.
- Root cause: `upsert_cinema()` DELETEs all rows then INSERTs inside **one transaction** (`with self.conn:`). Two films in the PDF normalize to the same slug `id` → second INSERT violates UNIQUE → the exception rolls back **the entire batch** → `cinema_events` table stays empty.
- Compounding: the 7 `allocine_vox` films ARE written to the `events` table (category `Cinema`), but `build.py:102` filters out category `Cinema` from the main list and the cinema section only reads the (empty) `cinema_events` table. **So all Chamonix cinema content is invisible.**
- Evidence: `CINEMA_EVENTS = []` in served HTML; film titles absent from index.html; `/healthz` cinema:0; manual run reproduces the traceback.
- Fix: catch duplicates (INSERT OR IGNORE / dedupe ids), remove the all-or-nothing transaction rollback, and either route allocine films into cinema or keep them consistently.

### 🔴 C2 — Daily briefing "EVENTS THIS WEEK" always empty/broken
- The morning-briefing cron queries `…/data/events.db` (`SELECT title FROM events WHERE…`).
- `data/events.db` is a **0-byte empty file with no tables** → the query errors (`no such table: events`).
- The live data lives in `…/data/chamonix.db` (39 published rows).
- Fix: point the briefing cron at `chamonix.db`. (Verified: same query on `chamonix.db` returns real events.)

## High

### 🟠 H1 — Footer renders "NaNj"
- `build.py` does `re.sub(r'<!-- build: .*? -->', f'<!-- build: {build_time} -->', html)`.
- This regex **also matches the JS regex literal** `/<!-- build: ([^ ]+) -->/` inside `showBuildTime()` (line 905), replacing it with a literal timestamp and destroying the `([^ ]+)` capture group.
- Result: `m[1]` is `undefined` → `new Date(undefined)` = NaN → footer shows `… AlloCiné · NaNj`.
- Fix: change the template's JS to match a value that isn't a plain `<!-- build: … -->` marker (e.g. a unique token), or make build.py's substitution targeted.

### 🟠 H2 — Review queue flooded with template garbage (664 open)
- 664 open review items; **431 from `chamonix_nightlife`**, nearly all confidence 0.262 (`below_confidence_threshold`), all near-identical generic titles ("Evening Cocktails", "Apéro & Tapas", "Craft Beer & After-Ski… ") with boilerplate descriptions and **no images**.
- The nightlife scraper generates hundreds of these per run; because they have no `image_url`, confidence ≈ 0.262 < the 0.3 threshold → every one piles into the review queue literally forever (nobody can manually review 431/month).
- Admin dashboard flags this itself ("Review Queue · 664 items pending review" in red).
- This also means **nightlife content never actually publishes** — only 1 nightlife event is live, so a headline feature is effectively missing.
- Fix: dedupe by venue+slot (not just title), drop generic no-description templates, add an expiry/auto-age-out for open items, and cap per-venue monthly output.

### 🟠 H3 — Stale/incorrect event content
- Published events contain stale copy, e.g. UTMB description: *"from August 25 to August 31, **2025**"* while the card date is 2026-08-24.
- Many summer "seasonal" events span months (start June 16 → end Sep 15), which is correct multi-day behaviour, but the schedule isn't being refreshed each season and scraped descriptions carry old year text.

## Medium

### 🟡 M1 — About page ships placeholder contact info
- `hello@chamonix-events.example` (reserved `.example` domain) and `@chamonix_events` are live on the public About page, each tagged "placeholder". Never filled in.

### 🟡 M2 — Map is fully dependent on external CDNs, no failure handling
- Leaflet loaded from `unpkg.com` and tiles from `cartocdn.com` on first map click (T20-F defer). Both CDNs return 200 from the host, and the logic is correct, but in sandbox/offline or if the CDN is blocked the map area silently stays 0px-high with no error or fallback message to the user. Verify in a real browser; consider a self-hosted fallback.

### 🟡 M3 — UTMB-style detail pages are sparse
- `ultra-trail-du-mont-blanc.html` renders title + links only (no image, no description body) — the detail template doesn't fall back to card content, so some events have thin detail pages.

### 🟡 M4 — Hero stat counters under-count recurring events
- Hero shows "5 this week · 1 today · 0 weekend"; overlap-counting the DB yields ~20/16/14. The hero uses exact `start_date` only (ignores multi-day `end_date` overlap and recurring spans) while the event list uses overlap logic → the two numbers disagree and "This weekend: 0" is misleading when weekend-spanning events exist.
